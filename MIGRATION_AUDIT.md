# Parlo learning-content separation — migration audit

## Version and scope
- Source: uploaded `parlo-develop.zip`; production application `index.html` + `data.json`.
- Original `data.json`: contentVersion **233**, **281** content modules.
- Migrated `data.json`: contentVersion **234**, **395** content modules (**114** added).
- Every original module and every original registry has been checked for exact JSON-value equality. None were deleted or modified.
- Curriculum: **38** units, **380** unit vocabulary entries, **12** original core verb entries (additional expanded registry verbs are generated by the app), **4** original core stories, and **4** original core dialogues. Data initialization exposes 153 verbs / 14 stories / 24 dialogues at runtime.

## What was moved
- Remaining Italian hardcoded audio tests and pronunciation examples, Italian feedback and placeholders, greeting/welcome content, and display text involving Italian terms.
- Writing feedback regex sources, Italian grammatical classifiers, curated lexical checks and selected source-language reference terms.
- Imperfect auxiliary forms and stems, imperfect and conditional conjugation endings, accented character-keyboard options, speech-vowel mappings, and vocabulary matching identifiers.
- The original 281 content modules remain present unchanged. The new entries use `CONTENT_*` keys; the HTML reads them through `__D.g(...)`.

## What intentionally remains in HTML
- Application shell and user-interface controls, routing, rendering and business logic.
- Implementations of conjugation, pronunciation approximation, exercises, input-validation algorithms, regular expressions describing general word parsing, language-code identifiers (`it`), and JavaScript property names such as `AUXP.avere` used by the algorithm. These are *code*, not an independent learning-content dataset.
- English UI text such as “Learn Italian” and “Italian voice” can remain in the HTML as presentation labels.
- Italian-specific pronunciation approximation rules and conjugation suffix tables have been externalized as ordered JSON datasets; the JavaScript loops and calculations remain in HTML.
- The **archived** `development/base.html` is an earlier development source and contains historical content; it is not loaded by the release `index.html`. The public ZIP excludes the development folder.

## Automated checks performed
1. JSON validation and exact preservation of every pre-existing module and registry.
2. Every literal `__D.g('...')` / `__D.g("...")` reference resolved to an existing JSON content module (408 references; 349 distinct keys).
3. JavaScript syntax checks on each `script[data-parlo-app]` block.
4. Chromium in-memory startup test: no page errors; 38 units loaded; welcome & main navigation loaded.
5. Side-by-side comparison of 6 navigation routes (`path`, `learn`, `cards`, `talk`, `me`, `set`): no exceptions in either version.
6. Comparison of sample verb forms, grade labels and writing feedback: matching output before/after.
7. The `parlo2` storage key was not changed, and original personal-progress `me.json` was not modified or included in release archives.
8. PWA service-worker cache identifier was updated to distribute the matching HTML/JSON release together.

## Limits: do not mistake this for complete parity proof
- Chromium tests were executed from an isolated in-memory page because live localhost navigation was blocked by the runtime administrator. Actual offline service-worker installation, mobile speech synthesis and device filesystem permissions were not tested.
- Six navigation routes and selected exercises are smoke tests, not a full interactive end-to-end regression of every practice module. Content indexes and progress IDs were preserved, but learner-specific migrations were not exhaustively verified.
- A static token scan cannot prove the absolute absence of every Italian-language literal. This migration concentrates user-editable Italian learning content and curated language reference sets in JSON while retaining algorithmic language rules in JavaScript. A literal-zero-Italian-token criterion would require moving code identifiers and grammar algorithms too, contrary to the requested separation.

## Deployment and user-data safety
- Back up currently deployed files, and export your private `me.json` before updating.
- Deploy `index.html`, `data.json`, `sw.js`, `manifest.webmanifest`, `icons/`, and `fonts/` together; do not mix JSON from different releases.
- Do not commit `me.json` or local learner backups to a public repository.
- On already-installed PWAs, complete the available update/reload flow. If content appears stale, close and reopen the app.
- Serving from `file://` may block loading `data.json`; use HTTPS or localhost.
- Keep your original `fonts/` assets in your repository. Font files are intentionally not redistributed in these packages.
- Differential browser tests matched **530** individual word-pronunciation approximations and **17** regular conjugation cases before/after.
